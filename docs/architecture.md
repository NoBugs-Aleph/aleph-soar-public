# 구성과 검증 흐름

실습 환경은 역할별 4대 PC로 분산합니다. 주소·접속 자격 증명·장비 설정 원본은 공개하지 않습니다.

| 영역 | 구성 | 목적 |
| --- | --- | --- |
| 서비스 | React / Flask / MySQL | 시민·직원·관리자 업무, 로그인 및 웹 이벤트, 대응 API |
| 네트워크 | pfSense / OpenVPN / Suricata | 구역 통제·팀 연결·네트워크 경계 로그와 IDS 경보 |
| 호스트 | Wazuh | 포털 웹 파일 무결성 감시와 복구 경로 |
| 관제·대응 | Graylog / n8n | 수집·정규화·상관탐지·대응 호출 |
| 사건 관리 | 티켓 저장소 / 보안 대시보드 | 탐지·조치·효과·해제·종료 이력 분리 |

## 시험 한 회의 목표

정상 상태 확인 → 합의된 입력 → 원문 수신 → 정규화·탐지 → 실제 대응 → 대상 효과 확인 →
티켓 기록 → 정상 사용자 영향 확인 → 원복 → 정상 동작 재확인.

- 수신 성공과 탐지 성공을 구분합니다.
- 대응 API 성공과 실제 접근 차단/복구 효과를 구분합니다.
- dry_run·합성 데이터·수동 호출을 자동 대응 실측으로 세지 않습니다.
- 티켓 닫기와 실제 차단 해제를 구분합니다.
- 다른 사건의 조치가 남아 있으면 원복 소유권을 확인합니다.

## 보안 3대 원칙

- 기밀성: 계정 공격과 세션·접근 통제.
- 무결성: 웹 파일 변조 탐지·정상 기준본 복구.
- 가용성: 요청 폭주와 정상 사용자 응답·회복 측정.

전체 경로의 완료 여부는 케이스별로 검증합니다. 개념도만으로 연결 완료를 주장하지 않습니다.
