## 성공 판정의 단계

1. **수신:** 원문과 식별자로 실제 도착을 확인합니다.
2. **탐지:** 정의·그룹·시간 창과 사건 생성 근거를 확인합니다.
3. **적용:** 호출 결과와 대상 목록·DB·방화벽 상태를 대조합니다.
4. **효과:** 새 접근·파일 내용·서비스 응답을 실제 확인합니다.
5. **정상 영향:** 별도 정상 사용자의 동작을 확인합니다.
6. **원복:** 해제·복구와 실제 재접근을 확인한 뒤 사건을 종료합니다.

실패·시간 초과·일부 적용에서는 상태가 불확실할 수 있습니다.
S10 첫 인수의 자동 해제 실패처럼, 수동 복구가 필요했던 회차는 그대로 기록하고 재시험과 분리합니다.

## S1에서 확인한 중복 관련 근거

10/28 첫 차단 구간은 Graylog 이벤트 16건에 대해 메인 n8n 실행 1회가 기록됐습니다.
이는 해당 구간의 알림 억제 관찰이며 모든 장애·동시성 조건에서 정확히 한 번 집행됨을 증명하지 않습니다.

해제 뒤 무공격 구간은 탐지 조건이 이미 성립하지 않는 시점입니다.
그 구간에 재차단이 없었다는 사실을 중복 억제 검증으로 대신 사용하지 않습니다.

## 시간 지표의 해석

효과를 사람이 기록하는 시각과 실제 적용 시각은 다릅니다.
S4·S10의 티켓 MTTR에는 수동 효과 기록 지연이 포함돼 있어 이를 자동 대응 소요시간으로 사용하지 않습니다.
11/4 S4 REPEAT02에서는 효과 기록이 재설정보다 늦게 남는 순서 역전이 있어, 해당 회차의 효과 기록 시각을 검증 시각으로 사용하지 않습니다.
S8도 검증 시각 필드의 누락과 실제 접근 관찰을 구분하며, 임의로 시간값을 보충하지 않습니다.

## 공개 범위

인증값·VPN 설정·원문 DB·내부 접속 주소는 게시하지 않습니다.
