# 대응 보호 장치와 확인 수준

자동 대응은 공격 대상을 제어하면서 정상 사용자를 유지하고 원복 가능해야 합니다.
아래는 설계·구현·격리 검증·현장 검증을 구분한 설명입니다.

| 보호 장치 | 목적 | 확인한 범위 | 남은 확인 |
| --- | --- | --- | --- |
| 대상·정상 출발지 분리 | 정상 사용자 오차단 방지 | S1 현장에서 다른 계정의 정상 로그인 확인. 입력/워크플로 보호 조건 격리 검사 | 같은 계정 정상 출발지·차단 직후 동시 대조 보강 |
| 재전송 키와 중복 처리 | 같은 요청·사건의 중복 집행 방지 | API·저장소 격리 검사, S1 현장 반복 이벤트 대비 메인 대응 1회 기록 | 전 케이스의 실제 재전송·불확실 응답·지연 조합 |
| 집행 경로 구분 | 앱·경계 조치를 같은 조치로 오인하지 않기 | 저장소의 경로별 중복·효과·해제 격리 검사 | S10 실제 앱·경계 동시 집행과 개별 원복 |
| 활성 조치·소유 확인 | 다른 사건이 유지하는 차단의 조기 해제 방지 | 조회·닫기·원복 관련 격리 검사 | 서로 다른 실제 사건이 같은 자원을 점유하는 현장 시험 |
| 효과와 응답 분리 | API 성공을 실차단 성공으로 오인하지 않기 | S1 차단 후 실제 접근 거부, 해제 후 접근 복귀 | 다른 케이스·타임아웃·부분 적용에서의 교차대조 |
| 승인 후 해제 | 담당자가 실제 상태를 확인한 뒤 원복 | S1 사람 승인·임시 호출·수동 기록을 통한 실제 해제 | 승인 해제 워크플로 전체의 현장 검증 |
| 기준본·해시 대조 | 웹 파일 복구 여부와 정상 배포를 구분 | S7 수동 Wazuh 복구·격리와 최종 verify 기록 | 자동 상관탐지부터의 전체 흐름·정상 배포 예외 |

## 성공 판정의 단계

1. **수신:** 원문과 고유 식별자로 실제 도착을 확인합니다.
2. **탐지:** 해당 정의·그룹·시간 창과 사건 생성 근거를 확인합니다.
3. **적용:** API 응답과 대상 목록·DB·방화벽 상태를 대조합니다.
4. **효과:** 공격 대상의 새 접근·파일 내용·서비스 응답을 실제 확인합니다.
5. **정상 영향:** 별도 정상 사용자의 동작을 확인합니다.
6. **원복:** 해제·복구 상태와 실제 재접근을 확인한 뒤 사건을 종료합니다.

실패·시간 초과·일부 적용에서는 상태가 불확실할 수 있습니다.
자동 재실행으로 덮기보다 기존 요청·영수증·소유·현재 대상 상태를 확인하는 기준을 둡니다.

## S1에서 확인한 중복 관련 근거

10/28 현장 기록에는 첫 차단 구간의 Graylog 이벤트 16건에 대해 메인 n8n 실행 1회가
기록돼 있습니다. 이 결과는 해당 구간의 알림 억제 관찰입니다.
모든 장애·동시성 조건에서 정확히 한 번 집행됨을 증명하는 결과는 아닙니다.

해제 뒤 무공격 관찰 구간은 탐지 조건이 이미 성립하지 않는 시점이므로,
그 구간에 재차단이 없었다는 사실을 중복 억제 검증으로 대신 사용하지 않습니다.

## 비밀정보와 공개 범위

인증값은 공개 예시·로그·캡처에서 제외합니다. 실제 운영 키·VPN 설정·원문 DB는 게시하지 않습니다.
공개본은 보호 설계와 확인 범위를 설명하며 장비에 즉시 적용할 운영 설정집이 아닙니다.
