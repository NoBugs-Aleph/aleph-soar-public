# 시나리오와 담당

팀의 필수 시나리오는 4종이며, 측정 케이스 ID는 6개입니다.

| 담당 | ID | 입력·판정 목표 | 대응·원복 목표 |
| --- | --- | --- | --- |
| A | S1 | 같은 계정·출발지의 저속 로그인 실패 | 공격 출발지 차단, 정상 사용자 유지, 승인 후 해제 |
| A | S4 | 로그인 실패와 성공의 결합 | 계정 잠금·세션 회수, 관리자 해제·정상 로그인 |
| C | S7 | 파일 무결성 경보와 같은 파일 웹 접근 | 변조 복구·새 파일 격리, 내용/해시/접근·정리 확인 |
| B | S8 | 웹 스캔과 로그인 실패 신호의 결합 | 출발지 차단·티켓·효과·원복 |
| B | S10 | 웹·인증·네트워크 경계 신호의 결합 | 앱·경계 조치를 구분해 확인하고 각각 원복 |
| D | S12 | 요청 증가와 응답 지연 | 정상 사용자 회복 확인, 출발지 제어·티켓·원복 |

이 표는 설계 목표입니다. 보강 전 확보·보강 후 실측·미검증은 [현황](verification.md)에서 확인합니다.

정상 입력, 임계값 직전, 시간 창 밖, 출발지·계정 혼재, 중복·지연,
다른 사건이 같은 자원을 사용하는 경우도 검증 대상으로 둡니다.
