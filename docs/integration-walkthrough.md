# S8·S10 통합 검증 해설 · 2026-11-03

이 문서는 A·D의 11/3 담당 일지에 기록된 입력·원본·대응·효과·원복 결과를 대조해 작성한 공개 요약입니다.
원본 파일과 고정 커밋은 [근거 기준](verification.md)에 있습니다. 내부 주소·계정·실제 사건 식별자는 생략했습니다.

## S8: 알림이 발생해도 대응 호출은 실패할 수 있음

| 단계 | 관찰·수행 내용 |
| --- | --- |
| 문제 | LIVE01에서 입력을 보냈지만 n8n 웹훅 미등록으로 호출이 404를 반환했고 차단·티켓이 생성되지 않았습니다. |
| 확인한 근거 | A의 포털 입력 원본과 D의 알림·웹훅 등록 상태를 대조했습니다. 입력 도착을 차단 성공으로 처리하지 않았습니다. |
| 보완 | D 담당에서 같은 워크플로를 UI로 재게시하고 등록 상태와 인증 없는 요청의 거부를 확인했습니다. |
| 새 회차 | LIVE02에서 상관탐지 뒤 포털 자동 차단·실제 티켓을 확인했습니다. |
| 효과 대조 | 공격 출발지는 403, 별도 정상 출발지는 로그인·민원 조회 200을 확인했습니다. |
| 원복 | 해제 뒤 공격 출발지도 200으로 복귀했고, 포털 잔여 차단 없음과 티켓 종료를 대조했습니다. |

워크플로 파일·게시 표시만으로 실제 웹훅 연결을 확정하지 않는 점이 핵심입니다.
LIVE01 실패와 LIVE02 성공은 별도 회차이며, 재게시만으로 모든 n8n 등록 문제를 해결한다고 일반화하지 않습니다.

## S10: 경계 차단과 포털 차단을 각각 확인하기

### PF 단독 인수의 실패와 재시험

첫 ACCEPT01에서는 실제 경계 차단 효과를 관찰했지만 자동 해제가 실패했습니다.
도구의 상태 판정이 설정 잔존을 놓치는 문제가 기록됐고, B 담당에서 수동 정리한 뒤 접근 복귀를 확인했습니다.
이 회차는 자동 인수 통과로 집계하지 않았습니다.

B 담당 도구의 읽기 재확인 대기·상태 판정을 보완한 r2 배포 뒤 ACCEPT02를 별도로 수행했습니다.
D 담당의 n8n 수동 호출로 시작해 차단·해제를 실행했고, 정상 접근 유지·최종 양쪽 접근 복귀·잔여 없음이 기록됐습니다.
이 재인수에서는 실패·재시도·B 수동 정리가 없었습니다. 상관탐지 검증은 다음 실제 회차와 구분합니다.

### 상관탐지부터 시작한 LIVE01

| 순서 | 관찰 | 구분한 사실 |
| --- | --- | --- |
| 1 | 웹·인증 요청과 경계 신호를 입력하고 상관탐지 확인 | 단일 로그 수신과 여러 신호의 판정을 구분 |
| 2 | 포털·PF 차단 적용과 티켓 확인 | 집행 위치를 분리해 기록 |
| 3 | 공격 출발지의 포털 원본 도착이 없고 정상 출발지는 200 | PF 상태·호출 결과와 접근 관찰을 함께 대조 |
| 4 | PF를 먼저 해제한 뒤 공격 출발지는 포털 403, 정상 출발지는 200 | 경계 해제 뒤에도 포털 차단이 남아 있음을 확인 |
| 5 | 포털도 해제한 뒤 두 출발지 200, 잔여 활성 조치 없음, 티켓 종료 | 실제 접근 복귀와 사건 종료를 함께 확인 |

PF와 포털이 함께 차단 중일 때 포털의 응답만으로 두 위치의 효과를 동시에 증명할 수 없습니다.
순차 해제를 통해 집행 위치별 효과와 복귀를 나눠 관찰했습니다.

## 이 결과로 확정하지 않는 것

- 해제 호출과 효과·해제 기록에는 담당자 조작이 포함됐습니다. 모든 단계가 자동 실행된 것은 아닙니다.
- 티켓 화면의 MTTR에는 수동 효과 기록 지연이 포함되므로 이를 자동 처리시간으로 발표하지 않습니다.
- 한 회차의 정상 사용자 대조는 모든 계정·출발지·동시 사건에서의 오차단 방지 보장이 아닙니다.
- PF 배포 r2의 현장 결과와 저장소의 최종 버전 동기화는 별도 확인 항목입니다.
- 실제 기업 운영 환경이나 장기간 고부하 안정성을 검증한 결과가 아닙니다.
